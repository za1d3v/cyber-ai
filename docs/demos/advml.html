Normalization alone makes things worse against a full attacker: blocked from l33t-speak, the attacker shifts to synonyms and padding. That's the arms race. Adversarial training (learning from attacked examples) closes these specific gaps, but new tricks would need new training.

3 · Data poisoning

The attacker can tamper with training labels (e.g. through a compromised labeling vendor or a feedback button) and marks scams as "not spam".

Defense: train a reference model on a small human-verified "golden" set (30 examples) the attacker can't reach, and drop any training example it strongly disagrees with. Protecting the data pipeline matters as much as the model.

What this shows a client: if you deploy ML for security (spam, fraud, malware, content moderation), attackers will probe it. Test it the way they will: adaptive evasion, data poisoning. Then budget for ongoing adversarial retraining and training-data provenance, not a one-time model. Maps to OWASP LLM04 (Data and Model Poisoning) and MITRE ATLAS evasion and poisoning techniques.
